# TwinShotNet

TwinShotNet 是一个实验性的 BepInEx 5 插件，为《Twin Shot Deluxe》增加由主机权威控制的 UDP 多人游戏功能。当前插件和协议版本为 **0.5.1**。所有玩家必须使用相同的插件版本和游戏版本；版本不匹配时会在连接阶段被拒绝。

## 架构

代码布局、生命周期、协议约束和测试覆盖说明见 [docs/architecture.md](docs/architecture.md)。

## 功能

- 主机以原生 60 Hz 运行原游戏模拟。
- 最多支持 4 名玩家，每名玩家使用独立的网络输入槽位。
- 房间建立后，主机和客户端使用游戏原生的角色选择/准备界面。远端玩家会被分配到可用的玩家槽位。
- 玩家可以占用槽位，选择粉色、橙色、紫色或蓝色，并在主机开始前准备。
- 开始比赛前加入或离开只会清除受影响槽位的准备状态；只有所有已占用槽位都准备好后，主机才能开始。
- 主机可以在原生角色选择界面看到远端玩家的加入和准备状态。比赛开始前有人离开时，剩余远端玩家会重新排列到最低可用槽位。
- 主机继续使用原生主题和关卡选择流程。客户端进入输入锁定的同步界面，并加载主机确认的确切主题和关卡。随机主题会在发送比赛数据包前解析为具体主题。
- 主机本地玩家继续使用原版 Rewired 键盘/手柄绑定。客户端使用方向键或 WASD 移动，Space/Z 跳跃，X/J 射击。
- 主机发送压缩后的视觉状态快照。客户端不会独立模拟战斗、碰撞、敌人 AI 或随机事件。
- 快照通过 UDP 分块传输。客户端使用有上限的 NACK 修复请求请求缺失分块，主机保留短期的聚合修复缓存。
- 主机的分数、生命值、存活状态和能力状态会发送到客户端，并应用到游戏内玩家 HUD。结算界面中的终局金币也会在原生结算流程中同步。
- 房间认证使用共享房间密钥和 `Assembly-CSharp.dll` 指纹。
- 插件可以选择抑制游戏的托管 Steam 重启/初始化调用，以便进行独立启动测试。

## 重要限制

本项目仍是实验性原型，并非完成品。客户端渲染主机发送的视觉状态，而不是运行本地游戏副本。目前没有客户端预测或回滚，因此远端输入必然包含网络延迟和插值延迟。

当前快照包含符合条件的动态 `SpriteRenderer` 对象以及玩家 HUD 状态。静态地图瓦片和 UI 层渲染器保留在客户端匹配关卡的本地，不作为动态对象复制。网格水面、特殊材质、粒子效果、声音时序、部分 UI、排序组、最终关卡切换、开始比赛后的重新连接以及所有场景生命周期都尚未经过完整回归测试。对于无法明确匹配的精灵，插件会刻意跳过，而不会替换成可能错误的资源；客户端状态栏会报告缺失的精灵。

主机通过原生游戏菜单选择主题和关卡，并使用主机存档处理原生 Continue/关卡选择行为。皮肤选择目前只提供四种基础颜色，不包含可解锁皮肤；主机本地玩家选择可解锁皮肤时，会回退到该玩家上一次使用的基础颜色。公开 UDP 流量未加密，请使用独立的房间密钥，不要重复使用账户密码。

## 安装

请单独安装 BepInEx 5.4.23.5 Windows x64。然后将以下文件夹复制到每位玩家的游戏目录：

```text
Twin Shot Deluxe/
└─ BepInEx/
   └─ plugins/
      └─ TwinShotNet/
         ├─ TwinShotNet.dll
         └─ LiteNetLib.dll
```

插件包中不要复制 `Assembly-CSharp.dll`、Unity DLL、项目文件、PDB 文件或 BepInEx 发行包。所有参与者都必须使用相同的两个插件 DLL。

## 构建和部署

在项目目录中执行：

```powershell
dotnet build -c Release -p:Deploy=true
dotnet run --project Tests/Tests.csproj -c Release
```

部署目标会将插件 DLL 和 `LiteNetLib.dll` 复制到默认的本地游戏安装目录。如需在不部署的情况下验证构建，请执行：

```powershell
dotnet build TwinShotNet.csproj -c Release -p:Deploy=false
```

当前自动化测试套件包含 **453 项检查**：232 项快照检查、110 项数据包边界检查、15 项槽位分配检查、36 项 Lobby 流程检查，以及 60 项输入/传输检查。

## 开始游戏

1. 在每台机器上启动游戏，并停留在主菜单。
2. 按 `F8` 打开 TwinShotNet 面板。
3. 主机输入 UDP 端口、长度为 12-128 个字符的独立房间密钥，然后点击 **Host**。
4. 主机将该端口转发为 **UDP**，不要使用 HTTP、HTTPS 或 TCP。Windows 防火墙必须允许游戏程序接收 UDP。
5. 每位朋友输入主机的公网 IP 或 DNS 名称（不要包含 `https://`），填写公网 UDP 端口和完全相同的房间密钥，然后点击 **Join**。
6. 原生角色选择界面会打开。主机本地玩家使用游戏原始键盘/手柄绑定；每位远端玩家只能操作分配给自己的槽位，选择基础颜色并标记 **Ready**。
7. 所有已占用槽位都显示 ready 后，主机才能开始。随后主机选择主题，并继续进入原生未完成关卡或选择指定关卡；客户端跟随主机确认的选择。

对于类似 `https://example.invalid:13478` 的 HTTPS 地址，客户端字段必须填写 `example.invalid` 和 `13478`，且服务商必须明确提供 UDP 转发。HTTPS 隧道无法承载此协议。普通路由器端口转发无法绕过 CGNAT；请使用支持 UDP 的中继或 VPN 覆盖网络。

## Steam 启动选项

插件首次启动时会创建 `BepInEx/config/local.twinshot.net.cfg`。以下选项默认关闭，修改后需要重启游戏：

```ini
[Startup]
SkipSteamRestart = false
DisableSteamInitialization = false
```

`SkipSteamRestart` 会抑制游戏托管层的 `SteamAPI.RestartAppIfNecessary` 调用，但仍保留 Steam 初始化。`DisableSteamInitialization` 还会将托管 Steam 初始化路径替换为明确的 false 结果，并优先于前一个选项。在该模式下，依赖 Steam 的功能不可用。

这些选项只会在 BepInEx 加载后修改托管启动代码，不会绕过原生启动器检查、所有权检查或许可检查。如果启用了独立测试，日志中应包含 `DisableSteamInitialization enabled` 和 `Startup reached; Steam initialization intentionally disabled.`。正常使用 Steam 时，请将两个选项都恢复为 `false`。

## 故障排查

- 检查 `BepInEx/LogOutput.log`，确认出现 `TwinShotNet 0.5.1 loaded`。
- `Unknown Host` 通常表示地址中包含 `https://`，或填写的不是 DNS 主机名。请将主机名和端口分别填写。
- 连接超时通常表示服务端点不是 UDP、端口映射错误、Windows 防火墙拦截了游戏，或主机位于 CGNAT 后方。
- 协议版本变化时，所有参与者都必须同时更新。版本 `0.5.1` 与旧协议版本不兼容。
- 客户端状态栏中的 `missing sprites` 表示部分资源无法安全匹配，并不代表游戏模拟失败。
- 修改房间前，请先从面板停止当前会话。比赛开始后不支持重新加入。

## 项目状态

仓库包含插件源码、协议实现、资源快照渲染器、自动化协议/输入测试，以及实验性的启动补丁。构建和单元测试成功并不能证明双机游戏已经完整可用。回归测试仍应覆盖移动、方向键、敌人、道具和分数、玩家死亡、关卡完成、断线以及公网延迟等场景。
